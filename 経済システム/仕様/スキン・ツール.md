# スキン・ツールアイテム仕様書

マーケットプレイス（[Web.md](Web.md)）で売買する `skin` と `tool` を、ゲーム内に反映する仕組み。共有 DB（`fje_active_skins` / `fje_tool_catalog` / `marketplace_*` / `account_links`）が唯一の接点で、Web からゲームへの HTTP 呼び出しは存在しない。

## 1. スキン

### 1.1 出品（Web）
- PNG のみ。**実寸 64×64 必須**（`imageSize` で検証）。
- mineskin.org（v2 キュー API。`MINESKIN_API_KEY` は任意）にアップロードして Mojang 署名付きテクスチャを取得し、`skin_texture_value` / `skin_texture_signature` / `skin_signed_at` を保存する（署名無しのテクスチャは Java 版クライアントが表示しないため）。Classic / Slim の判定結果は `skin_model`、生 PNG は `skin_png_data` に保存する。
- 署名機能追加前の出品は、fjew 起動時に `backfillLegacySkinListings()` が再検証・再署名する。失敗した出品は `paused` になる。
- 署名データの無いスキンは購入・使用ともにできない。

### 1.2 所有と使用
- 所有権は**購入した UUID 本人だけでなく、`account_links` 経由で同じ Web アカウントにリンクされた全 Minecraft アカウント（Java 用・Bedrock 用）で有効**。判定のたびに JOIN で再検証し、`marketplace_nfts.owner_uuid` との一致は不要。
- Web の「使用する」（`POST /api/marketplace/nfts/:nftId/use`）は `fje_active_skins` に `(owner_uuid, nft_id)` を UPSERT する。法人口座（`account_links` に無い UUID）は使用不可。「解除」（`/unuse`）は同じ Web アカウントの全 UUID から当該 NFT の使用を外す。
- ゲーム内: `/skin list`（所有スキンの番号付き一覧）、`/skin use <番号>`（所有権を再検証して適用）、`/skin reset`（`fje_active_skins` を削除して元に戻す）。

### 1.3 Java 版への適用（FJEconomy: `skin/SkinListener` + `SkinManager`）
- `AsyncPlayerPreLoginEvent` でログイン確定前に、使用中スキンの署名済みテクスチャをプロファイルに焼き込む。上書き前の元の textures は `SkinManager` のメモリに退避し、`/skin reset` で復元する（退避が無ければプロパティを削除）。退出時（`onQuit`）に破棄する。
- `/skin use` の途中適用では、プロファイルを更新して他プレイヤーに対して `hidePlayer` → `showPlayer` する。**本人の一人称視点は再接続するまで古いままの場合がある。**

### 1.4 Bedrock 観測者への適用（FJESkinBridge）
Java 版とは完全に別経路。Geyser が Java プレイヤーのスキンを自動変換するのとは別に、**Bedrock プレイヤー自身の見た目や、署名経路を通らない表示**を `SessionSkinApplyEvent` で一律に上書きする。

- **Geyser Extension**（`extension.yml`）であり Paper プラグインではない。Geyser / Floodgate が動くホスト（MS-KV, VMID 127）の Geyser `extensions/` に置く。Paper の `plugins/` に置いても読み込まれない（`paper-plugin.yml/plugin.yml が無い` エラー）。Java 21 以上が必要。
- 動作: スキン適用イベントのたびに `fje_active_skins → marketplace_nfts → marketplace_listings → account_links(所有者) → account_links(表示対象)` を JOIN し、同一 Web アカウントであることを再確認して `skin_png_data` を取得する。PNG を生 RGBA バイト列に変換し、`slim` なら `SkinGeometry.SLIM`、それ以外は `WIDE` を指定する。
- 結果（空も含む）は `skin_cache_ttl_seconds`（既定 30）だけメモリキャッシュするため、反映が最大でその秒数遅れる。
- DB エラー時は空を返し、上書きしない（その結果も TTL の間キャッシュされる）。

設定（`extensions/fjeskinbridge/config.yml`）:

| キー | 既定 | 内容 |
|---|---|---|
| `database.url` | `jdbc:mariadb://10.2.1.27:3306/fjeconomy` | 共有 MariaDB |
| `database.username` / `password` | `changeme` | 要設定。`marketplace_listings` / `marketplace_nfts` / `fje_active_skins` / `account_links` の参照権限が必要 |
| `database.pool_size` | 4 | 接続プール |
| `skin_cache_ttl_seconds` | 30 | キャッシュ秒数 |

HikariCP・MariaDB JDBC は `com.clustersprj.fjeskinbridge.libs.*` へ relocate して shade する。

## 2. ツールアイテム

便利アイテム（特殊な見た目・モデルを持つアイテム）をマーケットプレイスで売り、購入者がゲーム内の GUI から何度でも受け取れるようにする機能。

### 2.1 カタログ定義
`plugins/FJEconomy/tools/*.yml`（ファイル名から拡張子を除いたものが `tool_code`）。

| キー | 必須 | 内容 |
|---|---|---|
| `material` | 必須 | Bukkit の Material 名 |
| `display_name` | - | 表示名 |
| `lore` | - | 説明文（リスト） |
| `custom_model_data` | - | モデルデータ |
| `description` | - | Web の出品画面に出す説明（500 文字以内） |

起動時と `reload` 時に `fje_tool_catalog` へ同期される。Web の出品者は**ここにある `tool_code` を選ぶだけ**で、任意のアイテムを定義できない。Web 側のカタログ参照は `GET /api/marketplace/tool-catalog`（一般）と `GET /api/admin/tool-catalog`（管理）。

### 2.2 受け取り（`/tools`）
- `/tools` は 54 スロットの GUI（タイトル「購入アイテム」）を開く。**先頭 54 個までを表示し、ページングは無い。**
- 所有判定は `account_links` 経由で同じ Web アカウントの全 UUID を対象に都度行う。
- アイテムをクリックすると、所有を再検証した上でコピーを 1 個付与する（消耗しない・何度でも可）。インベントリが満杯なら足元にドロップ。
- ホットバーから `/tools` を呼ぶ導線は、サーバー側の Skript が担当する（プラグインの範囲外）。

### 2.3 権限による複製・転売対策
`ToolPermissionListener`（MONITOR）が、ログイン時に所有ツールごとに `fje.tool.<tool_code>` を `PermissionAttachment` で付与する。Skript 側で「アイテム名の一致 + この権限」を条件にすることで、他人から受け取った・複製された同名アイテムを無効化できる。購入直後はログインし直すまで権限が付かない。

## 3. 既知の差異・注意点

- FJESkinBridge の配置（MS-KV の Geyser `extensions/`）は 2026-08-30 時点で未実施。配置するまで Bedrock 観測者には反映されない。
- `/tools` は 54 個を超えるツールを持つとあふれる。
- スキンの本人視点の更新は再接続が必要な場合がある。
- ツール権限は購入後の再ログインまで付与されない。
