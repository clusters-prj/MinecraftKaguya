## 1. 概要

Vault 等に依存しない独自の経済システム。複数の Paper サーバー（mc1 / mc2 / mc3）が中央 MariaDB を共有し、どのサーバーで残高が変わっても即座に全体へ反映される。Web ダッシュボード・外部 API も同じ DB を直接読み書きする。

- 通貨: 整数のみ（`currency.symbol` = `¥`、`name` = `FJ Credits`、小数桁 0）
- サーバー間・Web 間の連携は DB 経由のみ（REST/RPC なし）
- 設定は `plugins/FJEconomy/config.yml`、ツール定義は `plugins/FJEconomy/tools/*.yml`

## 2. 起動順序

`FJEconomy#onEnable()` が次の順にマネージャを生成する。後段は前段の getter に依存するため**順序を変えてはいけない**。

1. ConfigManager（`ConfigMigrator` で config.yml を移行してから読み込み）
2. DatabaseManager（接続プール初期化 → `createTables()`）
3. EconomyManager
4. CommandManager（`/fj`, `/fjeadmin`）
5. ShopManager + ShopCommand（`/shop`）
6. GovernmentManager + GovernmentCommand（`/fjegovernment`）
7. LoginBonusManager
8. LinkManager
9. SkinManager + SkinCommand（`/skin`）
10. ToolManager（`tools/*.yml` → `fje_tool_catalog` へ同期）+ ToolGUI + ToolsCommand（`/tools`）
11. ArenaManager（ゾーン監視開始）
12. BuildRewardManager（開始）

登録するリスナ: PlayerListener / ShopUI / SkinListener / ToolGUI / ToolPermissionListener。
`onDisable` は DB を閉じる前に `arenaManager.restoreAllParticipants()` を呼び、アリーナ参加者の GameMode とインベントリを復元する。
`reloadPlugin()`（`/fjeadmin reload` または `/fj reload`）は config を読み直し、`database.url` / `username` が変わったときだけ DB を張り直し、ツールカタログを再同期する。

プレイヤー参加時（PlayerListener、MONITOR）: 口座の確保（`economy.starting_balance`）→ ログインボーナス判定 → アリーナの復元待ち判定、の順に処理する。

## 3. コマンド

| コマンド | 別名 | サブコマンド / 用途 |
|---|---|---|
| `/fj` | `economy`, `fje` | `balance`(`bal`) 残高 / `pay <プレイヤー名> <金額>` 送金 / `help` / `link` 連携コード発行 / `reload` |
| `/fjeadmin` | - | `give <名前> <金額>` / `take <名前> <金額>` / `set <名前> <金額>` / `reload` |
| `/shop` | `s` | `create <NPC UUID> <アイテム> <価格> [在庫]` / `delete <NPC UUID>` / `list [プレイヤー]` / `info <NPC UUID>` / `setprice` / `setstock` / `addstock` / `removestock`（いずれも `<NPC UUID> <値>`） |
| `/fjegovernment` | `fjegov`, `gov` | `balance` / `add <金額> [理由]` / `withdraw <金額> [理由]` / `distribute <プレイヤー> <金額> [理由]` / `ledger [タイプ] [件数]` / `tax` / `info` / `set <金額>` |
| `/skin` | - | `list` / `use <番号>` / `reset`（プレイヤーのみ） |
| `/tools` | - | ツールアイテム GUI を開く（プレイヤーのみ） |

### 3.1 権限

| 権限 | 既定 | 用途 |
|---|---|---|
| `fj.admin` | false | `/fjeadmin give|take|set` |
| `fj.reload` | false | リロード |
| `fj.shop.delete` | false | `/shop delete`（および ShopCommand 内の削除系チェック） |
| `fj.government` | false | `/fjegovernment` の各サブコマンド（`set` を除く） |
| `fj.government.set` | false | `/fjegovernment set`（残高の直接上書き。`fj.government` の子には含まれない） |
| `fj.arena.bypass` | op | アリーナ領域への進入・押し出しの除外（op も通過） |
| `fje.tool.<tool_code>` | 動的 | ログイン時に所有ツールごとに付与。Skript 側が名前照合と組み合わせて複製・転売を防ぐ用途 |

`plugin.yml` には `fj.use` / `fj.pay` / `fj.shop.create` / `fj.shop.manage` も宣言されているが、コード上では権限チェックされていない（誰でも実行できる）。→ §9

### 3.2 `/shop` の仕様

- `create` はコマンド実行者本人を店主として登録する。NPC の UUID は村人エンティティの UUID。アイテム名の妥当性は作成時には検証せず、購入時に `Material.matchMaterial` で検証する（不正なら購入前にエラー）。
- 在庫の省略時は `shop.default_stock`（100）。価格・在庫は 0 以上。
- `/shop list <プレイヤー>` は**オンラインのプレイヤーのみ**指定できる。

## 4. ショップ

村人（Villager）を右クリックすると、その UUID と `server.id` で `fje_shops` を引き、登録があれば通常の取引画面を止めて独自 GUI を開く（ShopUI）。

- GUI は 27 スロットのチェスト型。商品はスロット 13、周囲はガラス板で埋める（Bedrock の誤操作対策）。
- 店舗情報はエンティティ UUID ごとに 10 秒キャッシュする。購入後はキャッシュを更新する。
- **購入は 1 個固定**（数量選択なし）。

購入フロー:

1. 在庫チェック（1 個以上）
2. マテリアルの検証（不正なら中止）
3. 残高チェック
4. 在庫を確保（`stock >= 1` の条件付き UPDATE。同時購入でも在庫はマイナスにならない）
5. `EconomyManager#processPurchase`（1 トランザクションで 代金移動・税の政府納付・`fje_transactions` 記録・`fje_government_ledger` 記帳）
6. 失敗したら在庫を戻して終了（代金は動かない）
7. アイテム付与。インベントリが満杯なら足元にドロップ

## 5. 経済・税

- 価格は税込み。税額 = `price × economy.tax_rate / 100` を `BigDecimal` で計算し、`economy.rounding_method`（`HALF_UP` = 四捨五入 / `DOWN` = 切り捨て）で整数化する。
- 店主の受取額 = 価格 − 税額。**「支払総額 = 税額 + 受取額」が常に成立する。**
- 税は政府口座（`government.uuid`）に加算され、`fje_government_ledger` に `TAX_IN` として記録される。
- マーケットプレイス購入（Web）も同じ式で計算するが、税率・丸めは config.yml ではなく fjew の `.env`（`MARKETPLACE_TAX_RATE` / `MARKETPLACE_TAX_ROUNDING`）から読む。**ゲーム内の税率を変えたら `.env` も合わせて変更し、fjew を再起動すること。**
- `economy.allow_negative` が false（既定）の間、残高は負にならない。

### 5.1 政府口座

国庫。税収・ペットショップ売上が入り、建築ポイントやアリーナ賞金の原資になる。`/fjegovernment` で手動の入出金・分配ができ、すべて台帳に記録される。`set` は台帳に残らない直接上書きなのでデバッグ専用（`fj.government.set`）。`distribute` は**オンラインのプレイヤーのみ**対象。

### 5.2 ログインボーナス

`login_bonus.enabled` が true のとき、最終受取から `cooldown_hours`（24）以上経っていれば `amount`（500）を付与する。国庫からは出ず、台帳にも記録されない。受取日時は `fje_login_bonuses`。

### 5.3 アカウント連携

`/fj link` が 6 桁のワンタイムコードを `link_codes` に発行する（有効期限 `account_link.code_expiry_minutes` = 10 分）。Web の `POST /api/auth/link` がコードを消費し、`account_links` に UUID を紐付ける。Minecraft と Web の接点はこの 2 テーブルのみ。

## 6. config.yml

`config-version: 1`。`ConfigMigrator` が JAR 同梱の config.yml から不足キーを説明コメントごと補う（変更時は `.bak` を残す）。**項目の追加は同梱 config.yml の編集だけで既存サーバーに反映される。** キーの改名・削除をする場合のみ `CURRENT_VERSION` を +1 して `steps()` に手順を追加する。書き換えはコメントを保つため行単位編集（snakeyaml の `dump()` は使わない）。

| セクション | キー（既定値） |
|---|---|
| `database` | `url`（`jdbc:mariadb://10.2.1.27:3306/fjeconomy...`）, `username`, `password`, `pool_size`(10), `max_lifetime`(1800000) |
| `server` | `id`(mc1), `name` |
| `currency` | `symbol`(¥), `name`(FJ Credits), `decimal_places`(0) |
| `economy` | `tax_rate`(10.0), `rounding_method`(HALF_UP / DOWN), `starting_balance`(1000), `allow_negative`(false) |
| `shop` | `default_stock`(100), `sync_prices`(true), `sync_interval`(300) ※後 2 つは未使用 |
| `government` | `uuid`(00000000-0000-0000-0000-000000000001), `name`(GOVERNMENT) |
| `web_api` | `enabled`, `base_url`, `token` ※getter のみで未使用 |
| `logging` | `level`, `file`, `log_transactions` |
| `login_bonus` | `enabled`(true), `amount`(500), `cooldown_hours`(24) |
| `build_reward` | [建築ポイント.md](建築ポイント.md) 参照 |
| `account_link` | `code_expiry_minutes`(10), `website_url`(https://fjew.clusters-prj.com/) |
| `messages` | `prefix` と各種メッセージテンプレート（MiniMessage と `&` カラーコードが混在） |

`server.id` はサーバーごとに必ず異なる値にする（ショップ・建築ポイントの識別キーになる）。DB パスワードは各サーバーのローカル config にのみ置く。

## 7. 依存と shade

- softdepend: CoreProtect / customProtect（建築ポイントのみ使用。無くても起動する）
- HikariCP・JDBC ドライバ・SLF4J は `com.clustersprj.fjeconomy.libs.*` へ relocate して shade する（他プラグインとの衝突防止。外してはいけない）
- Java は compiler-plugin で 17 を明示（親 pom の 25 を上書き。意図的）

## 8. 運用ポリシー

- 本番デプロイは手動（Reposilite から jar を取得し `plugins/` へ配置、旧版 jar は必ず削除、`systemctl restart paper.service`）。詳細はリポジトリルートの CLAUDE.md を参照。
- 動作確認は実サーバーのコマンド実行と DB の直接確認で行う（テストコードは存在しない）。

## 9. 既知の差異・未整備

- `fj.use` / `fj.pay` / `fj.shop.create` / `fj.shop.manage` は宣言のみで未使用。
- `config.yml` の `shop.sync_prices` / `shop.sync_interval` / `web_api.*` は未使用。
- ショップ購入は数量 1 固定。`item_nbt` 列は未使用。
- `/shop list <プレイヤー>`・`/fjegovernment distribute` はオンラインプレイヤーのみ。
- ログインボーナスは国庫・台帳と無関係に通貨を新規発行する。
- `fje_transactions` の金額列は `INT`（`fje_balances.balance` は `BIGINT`）。
- マーケットプレイスの税率が fjew の `.env` と config.yml の二重管理になっている。
