# 建築ポイント仕様書

CoreProtect のブロックログを定期集計し、建築量に応じてポイント（通貨）を国庫からプレイヤーへ付与する。実装は `build/BuildRewardManager`、管理画面は Web の `build-admin`。

## 1. 前提

- CoreProtect API v9 以上が必要（customProtect 等のフォークも `instanceof CoreProtect` での検索で利用可）。プラグインは遅延解決するため、CoreProtect が無くても FJEconomy は起動する（集計だけが動かない）。
- 各サーバーが自分の `server.id` 分だけ集計する。複数サーバーで動かす場合、`server.id` を必ず別の値にする。

## 2. 定期集計と付与

### 2.1 タイミング
`build_reward.interval_hours`（既定 3）ごとの境界で実行する。境界は 0:00 起点。24 の約数でない値は切り捨てて丸める。起動時には**直前の 1 期間分**を一度だけ実行する。二重付与はユニークキー `uk_period_player (server_id, period_start, minecraft_uuid)` で防ぐ。

### 2.2 集計
- `performPartialLookup`（action: 破壊 = 0、設置 = 1）で期間内のログを 5000 件ずつ取得する。上限は 100 万行。
- ロールバック済みのエントリは除外する。
- 対象プレイヤーは `fje_balances` から政府口座を除き、`last_update` の新しい順に上位 `max_players` 人。
- `excluded_materials` に指定したブロックは数えない。

### 2.3 スコアとポイント
- `subtract_breaks` が true: `score = max(0, 設置 − 破壊)`、false: `score = 設置`。
- `score ≥ min_blocks` のときだけ `points = score × points_per_block`。
- `max_points_per_period` > 0 なら上限で頭打ち（0 は無制限）。

### 2.4 付与（プレイヤーごとに 1 トランザクション）
1. `fje_build_rewards` に記録
2. `from_government` が true なら国庫から減算
3. プレイヤー残高に加算
4. `fje_transactions` に記録（`item_id = BUILD_REWARD`、buyer = 政府）
5. `fje_government_ledger` に記録（`BUILD_REWARD`、説明 `To: <名前> - 建築ボーナス（設置 N ブロック）`）

国庫残高が足りないプレイヤーは警告ログを出してスキップする（付与されない）。`from_government` が false の場合は国庫を介さず通貨を新規発行する。

## 3. 設定（config.yml `build_reward`）

| キー | 既定 | 内容 |
|---|---|---|
| `enabled` | true | 機能の有効 / 無効 |
| `interval_hours` | 3 | 集計間隔（24 の約数） |
| `points_per_block` | 1 | 1 スコアあたりのポイント |
| `subtract_breaks` | true | 破壊数を差し引く |
| `min_blocks` | 10 | 最低スコア（未満は付与なし） |
| `max_points_per_period` | 3000 | 1 期間・1 人あたりの上限（0 = 無制限） |
| `from_government` | true | 国庫から支払う |
| `excluded_materials` | [] | 集計から除外するブロック |
| `max_players` | 500 | 1 回の集計対象人数 |
| `query_poll_seconds` | 10 | Web 集計リクエストのポーリング間隔 |
| `max_lookup_days` | 30 | Web 集計で遡れる最大日数 |

## 4. Web からの任意期間集計

管理者が `build-admin` から期間とサーバーを指定してリクエストを登録する。**ポイントは付与されず**、ランキング表示用の集計だけを行う。

- `GET /api/admin/build/servers`: 選択肢となるサーバー ID 一覧（`fje_build_rewards` と `fje_transactions` から取得し、`WEB` / `ARENA` / `API_BOT` の擬似値は除外）。
- `POST /api/admin/build/queries`: リクエスト登録（日時は `datetime-local` 形式も可。`YYYY-MM-DD HH:MM:SS` に正規化）。
- `GET /api/admin/build/queries` / `GET /api/admin/build/queries/:id`: 状態と結果。

プラグイン側の処理:
1. `query_poll_seconds` ごとに、自サーバー ID の `PENDING` を取得し、`RUNNING` として確保する。
2. 集計して `fje_build_query_results` に保存し、`DONE` にする。
3. 失敗時は `ERROR` と `error_message` を記録する。理由: CoreProtect 未導入、期間が不正、`max_lookup_days` より古い、結果が上限で切り詰められた、など。
4. 起動時に、前回の停止で `RUNNING` のまま残った行を `PENDING` に戻す。

## 5. 既知の注意点

- 対象プレイヤーは `last_update` 順の上位 `max_players` 人のため、長期間ログインしていないプレイヤーは集計対象から外れる。
- 国庫不足のプレイヤーはその期間の分が付与されず、後から補填されない。
- 担当サーバーが停止していると Web 集計リクエストは `PENDING` のまま残る。
