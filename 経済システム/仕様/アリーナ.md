# アリーナ・優勝者予想ベット仕様書

管理者が Web で登録した対戦イベントを、Paper プラグイン（`arena/ArenaManager`）が検知して領域管理・勝敗判定・賞金とベットの精算まで行う。Web 画面は `arena`（一般・ベット）と `arena-admin`（管理）。

## 1. データ

`fje_arena_events` / `fje_arena_participants` / `fje_arena_bets`（定義は [DB.md](DB.md) §3.6）。

| status | 意味 |
|---|---|
| `ACTIVE` | 開催中。領域管理とベット受付の対象 |
| `RESOLVED` | 勝者が決まり精算済み |
| `CANCELLED` | 管理者がキャンセル。ベットは全額返金 |

## 2. 管理者の操作（Web）

`POST /api/admin/arena/events`（管理者のみ）で登録する。

| 項目 | 内容 |
|---|---|
| `name`, `world` | イベント名、ワールド名（必須） |
| `x`, `y`, `z`, `radius` | 中心座標と半径（数値、半径 > 0） |
| `prize_amount` | 優勝賞金（0 以上の整数。省略時 0） |
| `participants` | 対戦プレイヤー 2 名以上。UUID またはプレイヤー名（`fje_balances` に存在すること） |
| `loadout` | 初期装備（任意）。1 行 1 アイテムの `MATERIAL:個数`（個数 1〜64、最大 40 行）。例 `DIAMOND_SWORD:1` |

- `GET /api/admin/arena/events` で全ステータスの直近 100 件と参加者を取得。
- `POST /api/admin/arena/events/:id/cancel` は ACTIVE のみ対象。`PLACED` のベットを全額返金（`REFUNDED`）し、status を `CANCELLED` にする。

## 3. プラグインの動作

### 3.1 ポーリングとゾーン監視
- イベント一覧は 5 秒ごと（100 ticks）に DB から読み直してキャッシュする。
- ゾーン監視タスクは 0.5 秒ごと（20 ticks 後開始、10 ticks 周期）。`PlayerMoveEvent` / `EntityDamageByEntityEvent` は高頻度パスなので、判定は毎回 DB を叩かずキャッシュで行う。
- ゾーン判定は**円柱**（XZ 平面の半径のみ。Y は無視）。

### 3.2 参加者
領域に入った参加者は次のように扱う。
1. GameMode を SURVIVAL に変更。
2. インベントリ・防具・オフハンドを `ParticipantState` としてメモリに退避。
3. `loadout` があれば付与（防具・盾は自動装備）。

イベント終了（RESOLVED / CANCELLED）で GameMode とインベントリを復元する。復元時にプレイヤーがオフラインなら、次回ログイン時（`handlePlayerJoin`）に復元する（イベントがまだ ACTIVE の間は復元しない）。サーバー停止時（`onDisable`）は全員を復元する。**退避はメモリ上のみ**なので、サーバーがクラッシュすると復元できない。

### 3.3 非参加者の排除
`fj.arena.bypass` を持たない（op でもない）非参加者が領域に入ると押し出す。押し出し位置は中心から半径 + 2.0 の地点へ投影し、立てる Y 座標を探索する（最大 4 ブロック下まで）。警告メッセージは 3 秒に 1 回に絞る。

### 3.4 PvP
領域内の参加者同士のダメージは許可する（WorldGuard の PvP 禁止設定より優先して再許可）。

### 3.5 勝敗判定
`PlayerDeathEvent` で、ACTIVE なイベントの参加者同士かつ領域内（半径内）のキルが起きたとき、キルしたプレイヤーを優勝者としてイベントを解決する。

1. status = `RESOLVED`、`winner_uuid`、`resolved_at` を記録。
2. 賞金を国庫から優勝者へ支払う（`governmentManager.distributeGovernmentFunds`、台帳 `FUND_DISTRIBUTE`、説明 `アリーナ優勝賞金: <名前>`）。
3. ベットを精算する（§4）。
4. 全体にブロードキャストする。

## 4. ベット

### 4.1 受付（Web）
`POST /api/arena/events/:id/bet`（要ログイン）。

- 入力: `predicted_uuid`（優勝予想）、`amount`（1 以上の整数）。
- 条件: イベントが ACTIVE、予想対象がそのイベントの参加者、残高が足りること。
- 賭け金は受付時に残高から即座に引き落とす（`fje_arena_bets.status = PLACED`）。
- 賭ける口座は、ログイン中の Web アカウントに**最初に紐付いた** Minecraft UUID。
- 同じイベントに複数回・複数の対象へ賭けられる（制限なし）。参加者本人が自分に賭けることも可能。

### 4.2 精算（プラグイン、1 トランザクション）
- 当たりが 1 件以上: パリミュチュエル方式。総賭け金（PLACED 全体）を、当たった賭け金の比率で按分する。`payout = totalPool × amount / winningPool`（`BigInteger` で計算し端数は切り捨て）。当たり = `WON`、外れ = `LOST`。
- 当たりが 0 件: 全ベットを返金（`REFUNDED`、`payout_amount = amount`）。
- 払戻・返金は残高に加算し、`fje_transactions` に `server_id = ARENA`、`item_id = ARENA_PAYOUT` / `ARENA_REFUND` で記録する。

端数切り捨てにより、総払戻額は総賭け金より最大でベット件数分だけ少なくなりうる（差額は誰にも配分されず消える）。

### 4.3 一般向け API
- `GET /api/arena/events`: ACTIVE のイベント、参加者、現在のベット総額（`bet_pool`）。
- `GET /api/arena/my-bets`: 自分に紐付いた全 UUID のベット履歴（直近 50 件）。

## 5. 既知の差異・注意点

- 管理者キャンセルの返金（Web 側）は `fje_transactions` に記録されない（残高の加算と `fje_arena_bets` の更新のみ）。プラグイン側の自動精算の返金は記録される。
- ベット中の口座は「最初に紐付いた UUID」固定で、送金元を選べない。
- 退避したインベントリがメモリ保持のため、クラッシュ時に失われる。
- 初期装備のマテリアル名は Web 側では書式のみ検証し、実在確認はしない。
